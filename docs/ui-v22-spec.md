# UI v22：ランダム効果の候補検索

原本r20を変更せず、保存済みの補足表からランダム付与を構造化する。検索・表示を追加するためUI v22とする。データのみの更新ではUI番号を上げない既存方針を維持する。

## データと根拠

保存29 HTMLの38候補表（原本補足欄の35表＋既存random_effect_optionsの3表）を61スキルへ対応付けた。原本全1,419カード/24,025項目・全ID/8手修正を保持。基礎は1,466カード、47個別ページは引き続き指定保留。新しいWiki通信やGoogle書込みは行わない。

既存19,850効果を保持し、random_grantを61追加して計19,911効果にする。候補を通常のrate_up等へ展開せず、random_pool.optionsへ保持する。61付与のうち60は候補を構造化、【ROOTS】1スキルの3候補は原文に倍率の単位がないためpartial。0.2UPを0.2倍や20%と推定せず、未確認候補3件を表示して候補による絞り込みから除く。以前の不明確な5条件の再発ではない。

原文の付与個数は親fact、候補の値/属性/継続は子optionへ分ける。交換数の1回を継続1ターンにしない。個人アピール倍率への加算は既知人物名と明記された「倍」を必須にする。フレキシブルは名称と期間だけを保持し、仕組みを補わない。リザレクションはメンタル0時・回復率・期間・使用回数を区別する。

保存R01 random節に同じ効果が複数付与される場合があると明記されている。same_option_can_repeat=trueとし、選択確率はunknown。均等確率とは推定しない。候補テキストの全文は公開せず、型付きの事実と原セル座標だけを配布する。

## 原表との対応付け

source_positionsの直前ライブ表に候補表を対応させる。MB明記の見出しはmb_liveを必須とし、MBを省略した見出しは実際に直前のMB表が確認できる場合だけ採用する。原文section_anchorを跨ぐ対応、複数kind、重複表、付与のない表は変換失敗にする。通常/＋とMBの候補を混ぜない。

35補足表の全セルを保存HTMLと照合。既存取得器が見出し末尾の脚注*1を除去していた4箇所は、本文差分と区別して監査へ記録した。原本や取得原文を修正していない。全29 HTMLのSHA、204位置、131フィールドを確認（4見出し脚注差分を除いて一致）。

## 検索・表示

「効果の種類 → ランダム効果（候補から探す）」を明示的に選択する。属性・継続ターン・キーワードは同じ候補内で一致する必要がある。通常のUP検索や種類未指定の属性フィルターには、偶然付与される候補を混入させない。受け手が記載されていない候補を自身と推定しない。

詳細に付与個数、候補（または）、未確認候補数、重複付与可能・確率不明・付与非保証を表示する。URL effect_type=random_grant、選択、再読込、解除、一致強調に対応。ランダム候補の数値から始まるキーワードは数値境界も確認し、40%UPが140%UPへ誤って一致することを防ぐ。従来の自由キーワード検索の部分一致仕様は維持する。

旧不変バンドルも引き続き検証可能。新しいランダムフィルターでは旧版に候補factがなければヒットさせない。ライブ全体のpartialを保持し、全効果の完全構造化を主張しない。
