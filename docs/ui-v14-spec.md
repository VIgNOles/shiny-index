# UI v14：効果によるカード検索

更新日：2026-10-11。UI版は画面・操作の変更時だけ更新する。データのみの追加・修正ではUI版を変えず、基礎版・詳細版・原本revisionで管理する。今回のv14は効果検索用の操作と表示が変わるため更新した。

## 目的と操作

必要なスキルを持つカードを探す。「スキルから探す」に効果の種類・対象・継続ターン以上の3条件を追加した。例：体力回復＋体力、継続UP＋Dance＋5ターン以上、固有のアピール値UP。スキル名・発動場面・対象アイドル・グループ名・Lv式はキーワードでも検索できる。発動条件の選択はパッシブ専用と明記した。

新しい3条件とキーワードは同じスキルの同じ効果に一致させる。別の効果や別のスキルから対象・継続ターンを借りない。既存のLink等の機能条件はライブスキルだけに適用する。思い出のLink/チャージ追加効果は通常効果と混ぜない。

詳細の中では一致するスキルを先に表示し、該当効果を文字と背景で強調する。他のスキルも残し、パネル等の原本順序は書き換えない。条件解除で元の表示順へ戻る。条件はURLに保存し、再読込・戻る/進む・条件チップ・リセットに対応する。320/390pxは一列で操作できる。

## データの扱いと限界

`effect_details`を詳細JSONへ追加。既存フィールド・ID・取得原文・手修正・版付きの旧ファイルは不変。Google原本r19から再生成する派生データなので原本revisionとGoogle Sheetを変更しない。

サポートスキル5033項目は、効果・Lv式・発動場面・確率・対象を分離する。数値がない記載はamount_unknown、確率不記載はunknownとして保持し、推測しない。取得表にある最大スキルLvでの値を式と併記し、カードのサポートLvとスキルLvを混同しない。非数値の滞在率・アドバイス等は定性的な効果であり、増加量の確定を主張しない。

原文に「するとで」とある同名テンションマスタリー上限5項目は、スキル名と対象・式が完全一致する既知の表記だけを受理し、source_notation=extra_particle_deを付けて画面に注記する。原文は修正しない。これらは以前解消したパッシブ条件5項目とは別で、原文表記の扱いである。

固有アビリティ110項目では対象アイドル、グループ、編成ユニット数、効果が変動する要因、ダメージまで等の制約を効果と結び付ける。グループ名の内部空白を保持する。アピールフェイズ開始時の確率とバフ値・継続ターンも分離する。

ライブ等は、アピール倍率・範囲・最大値・全観客対象も分離する。認識できるUP/DOWN/CUT/興味倍率に隣接した継続ターンだけを付け、Link/Plus等の区間を保持する。最大値は最大値と明記し、複雑な条件・未知の表記は無条件効果へ変換しない。ランダム候補を持つスキルは既存の候補構造を保持し、この派生モデルへ同時発動効果として変換しない。既存の数値抽出は互換のため保持する。ライブ効果全文の構造化完了は主張しない。対応範囲を画面へ明示し、検索0件が不存在の証明でないことを説明する。

Pステージ/適正・Sファイトは対象外。47個別ページ、実在基礎新規カードの本番追加実証は保留。CSVの画面導線を非表示のまま維持する。
