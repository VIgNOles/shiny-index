# UI22を維持したデータ補完：メンタル消費に応じた最大UP

保存原本r20を再変換し、16カード(P10/S6)・パネル26/MB4の30スキルについて、メンタル減少量で変わる継続UP効果を検索可能にする。検索・表示形式を変更しないため、UI v22を維持して詳細データ版だけを更新する。

## 根拠と対象

保存16 HTMLの60セル位置・30フィールドを全数照合。原文は「自身のメンタルをX%減らし、属性最大Y%UP」と、隣接する「減少値が多いほど効果UP」「Nターン」の括弧で構成される。2種類の括弧順序（増加条件→期間、期間→増加条件）とVo/Da/Vi等の既知属性表記を扱う。

従来の変換は最大UPをGrowの区間に限定し、括弧の間に増加条件がある表記にも対応していなかったため、通常/MBの30効果が検索用構造へ出ていなかった。取得原文や原本が欠けていたのではなく、変換の未対応である。

原本全1419カード/24025項目・固定ID/8手修正/非効果項目/coverageを保持する。既存19911効果を一つも失わず30 rate_up factを追加し、計19941効果。既存メンタル消費101factやランダム付与61factの値・構造も変更しない。原本r20/native採用履歴ccdbを書き換えない。Wiki通信/Google書込みは0。

## 構造化する範囲

自己消費の節と最大UPを、同じ原文区間の隣接した一組として確認できる場合だけ採用する。省略された単位、遠くの別効果の数値、未知の前置き、条件括弧内を根拠に最大UPを作らない。既知表記以外の一般的な最大UPを一律に解禁しない。

新factはmetric=rate_up/maximum=true/targets=属性/unit=percent/turns=明記期間/restrictions.scaling=mental_spent。メンタル消費率X%と最大UP率Y%を別factに保持する。消費率から実際のUP率や係数を計算・推定しない。最大値を確定付与量と表示せず、既存の「最大Y%」「減少値が多いほど効果UP」を使う。ライブ全体のpartialを保持する。

「自身」はメンタル消費の対象であり、後続UPの受け手として継承しない。Link/Plus/Growの属性・条件・期間へ継承せず、MB値を通常値へ混ぜない。既存Grow表記で重複factを作らず、後続の既知restrictionも保持する。元のconditions/mechanic rulesは変えない。
