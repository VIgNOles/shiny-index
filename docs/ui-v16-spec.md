# UI v16：ライブの発動条件とGrowのLv上昇条件

2026-10-11。原本r19/1419カード/24025項目、基礎r7/1466を保持する。画面の条件表示と検索結果が変わるためUIをv16に更新する。データのみの追加ではUI番号を更新しない。

## 区別する意味
- Plusのパッシブ個数は「現在発動中のパッシブ」の個数。累積発動回数やステータス効果の個数ではない。全員参加との省略された複合節はAND。
- 注目度UPの付与個数とユニット全員参加はAND。履歴のユニット人数または人物名という共有された文尾はORを保つ。
- Refrainの人物別アピール倍率UPは、対象人物と必要な付与個数を保持する。一意な既知略名だけを正規名にする。
- Growは現在の付与状態ではなく、付与・履歴追加・観客のリアクション対象になるイベントを数える。ダメージを実際に受けた回数へ読み替えない。複数候補の「又は」はOR、人物名3人が共有するアピール倍率UPの文尾も各候補に保持する。
- Grow Lv上昇は翌ターン反映、必要個数に満たない端数は繰越、使用後そのライブスキルのLvは0。Lv別の全効果や実戦シミュレーションを実装したとは扱わない。
- Growの最大UP効果14件をmaximum=trueで追加する。通常の一定効果量や他の場面の未知の最大効果と混同しない。数値・対象・隣接した継続ターン・Grow条件を同じ効果へ結び付ける。

## 公開派生データと互換性
新規文法はsrc/live_conditions.pyに分離し、パッシブ条件の既存文法と5890項目の派生結果を変えない。取得列・手修正6件・固定ID・既存全フィールドとcoverageを維持する。

effect_details.effects[*].mechanic_conditionはoptional。roleはactivationまたはgrowth、statusはstructured。activationは既存のAND/OR述語にactive_passive_count、idol_appeal_boost_countを追加する。growthはstatus_granted、idol_appeal_boost_granted、history_unit_added、audience_reaction_targetedのイベント型を使い、events_per_level、level_up_timing=next_turn、carry_over=true、reset_on_use=trueを持つ。人物名・ユニット・状態名・数値はallowlistで検証する。新文法は区間先頭の完全な1括弧だけを認識し、未知の末尾や候補・重複・余分な括弧を部分的に採用しない。

旧activation_condition={status:unsupported}は残す。旧UI v15は新optional情報を無視して従来の未構造化表示を維持し、新UIはmechanic_conditionを優先する。詳細schema1.0の追加互換フィールドであり、旧不変バンドルは書換えない。

数値効果を認識できない区間はeffect_details.mechanic_conditionsにslot/segment/scope/conditionを格納する。効果の数値を捏造せず、条件だけ表示・キーワード検索する。今回残る独立条件は5区間。数値効果に付けた同じ条件は独立条件へ重複登録しない。

## 表示と検索
Plus/Refrainは「発動条件」、Growは「Grow Lv上昇条件」と表示する。付与個数、翌ターン反映、端数繰越、使用後Lv0を示す。検索欄のラベルにもLv上昇条件を追加する。パッシブ条件の要素選択は引き続きパッシブ専用。

効果種類・対象・継続ターンが指定された場合、条件キーワードも同じ認識済み効果に一致する必要がある。独立条件と別の通常アピールの数値を結合しない。独立条件は効果フィルターがないときだけ検索・強調する。旧データ、URL復元、リセット、検索と強調の同一判定を維持する。

## 出典と検証範囲
保存R01「スキル効果の解説#extra_004」と、R01から参照されたR02「フェス#growup_appeal」を使用した。R02だけ本文1＋robots1を取得成功、再試行0。単ページ共有ゲート・排他・完了後60秒・失敗停止を使用し、全カード再取得はしない。原HTML・SHA・原セル・解釈根拠はprivate/audits/ui16-condition-inventory-20261011.jsonとui16-source-proof-20261011.json。本文を配布しない。

### キーワード単独時の一致表示

効果の選択がないキーワード単独検索でも一致した項目を先に出して該当グループを開く。数値効果・独立条件の強調は、それぞれ同じ表示文に全キーワードが一致する場合だけ行う。旧UI用画面試験は「必ず閉じている」という前提を除き、閉じているときだけ開くようにした。新UIの独立条件を検索した実画面試験でこの差を確認した。

## UI番号を維持する取得済み効果の補完

公開確認後の棚卸しで、全観客への興味効果、ダメージまで続く効果、クイックスキルのコスト括弧、日本語属性表記、ランダム候補との併存を理由に確定効果まで検索対象から外れている項目を確認した。既存のmetric/maximum/audience/restrictions/scopeだけを使用して補完する。表示コード・操作は変更しないためUI v16を維持し、詳細内容版だけを更新する。

「ダメージを受けるまで」は固定ターンにしない。思い出ゲージの即時増加とコスト括弧は、継続するゲージUPと別にする。ランダム効果の候補表は従来どおり代替候補として保持し、原セルに明示された「ランダム効果N個付与」と併存する通常/Plusの確定効果だけを追加する。候補だけの入力は同時発動する効果にしない。興味最大とパッシブ強化最大はGrow限定で最大値として扱う。興味の最小値・熱狂・リザレクション等の新しい意味を既存型へ押し込めない。

今回のデータ補完は131項目・142効果。旧確定効果はすべて保持。認識済み効果の区間条件は589対応、独立Grow条件は2、効果全体が未構造化の項目は23→6。ただし部分的にしか認識できない複合効果はこの6件以外にもあり、全効果の網羅率ではない。raw49区間の対応済みという判定は変わらない。
