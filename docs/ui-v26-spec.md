# UI v26：スマホで直接探せる検索入口

2026-10-12。実装・総点検・公開確認済み。ユーザー原文はTASK.md。UI25の検索の意味を保ち、スマホの入口だけを見直す。

## 採用判断

- カード検索、P/S、レアリティ、人物の一段の開閉、シリーズ8区分、スキル・性能の一段の開閉を通常ページに置く。シリーズは直接選べる。ユニット配下のアイドルは追加の折りたたみを作らない。
- 通常ページの条件はPC/スマホとも即時反映。長い選択肢は既存の開閉を使う。人物と性能の入口を一つの無名なパネル内へ隠さない。
- スマホの「詳しい条件を設定」はライブの種類/追加機能、発動条件の要素、対象/継続、実装日/詳細収録状態、旧リンク条件を開く。詳細だけ編集→一括適用。適用前の通常ページの条件/件数/URLは変えない。キャンセル/戻る/Esc/幅変更で破棄する。
- 件数0の意味を入口ラベルに混ぜない。選択済みなら「詳しい条件を変更（n条件）」と明示。候補件数は適用ボタンに表示する。
- 適用不能な条件は通常ページにも表示し、詳細編集中のエラーはパネル内で直せる。詳細取得失敗時は通常/詳細両方の性能入力を無効化し、基礎検索を維持する。
- データ/原本/固定ID/13手修正/検索判定/旧URLは変更しない。UI版と全資産クエリのみ26へ揃える。

## 検証・総点検の範囲

1. 常用条件の直接操作と即時結果、詳細だけの下書き/取消/適用/履歴、6幅/タッチ/キーボード/読み込み失敗。
2. 既存ユニット/シリーズ/スキルの正例・否定例、同じスキル/同じ効果の粒度、並べ替え/続きを表示/詳細/旧URL。全表示選択肢を実データで照合する。
3. 公開全ファイル一致、匿名公開のPC/スマホ確認、CI、UI25切戻し候補、保護SHA、復旧ZIPを確認し記録する。

範囲の限界：全ゲーム情報の独立公式網羅・実機Safari/全Android/スクリーンリーダーの全面適合は保証しない。47件・新規カード本番追加の保留、原文の欠損/期間スキップ、対象外を維持する。

## 再現と切戻し

既存のPythonセットアップ後、npm ci と npx playwright install chromium。npm test、npm run test:ui（6幅＋タッチ2設定）、npm run test:search-ui（通常/詳細の総点検）を実行する。Windowsの既存EdgeはUI_BROWSER_PATHで指定可能。公開確認はUI_BASE_URL=https://vignoles.github.io/shiny-index/、UI_EXPECTED_VERSION=ui-v26。依存追加なし。

UI25正常保存点はui-v25-20261012。python scripts/build_ui_rollback.py --ref ui-v25-20261012 --source site --output private/site-ui25-restore-candidate で新しい隔離候補を作り確認する。原本とデータを保ったまま5画面資産だけを戻せる。本番切戻しは実施しない。UIのみ更新時は全uiクエリも同じ番号へ揃え、データだけの更新時はUI26を維持する。
