この文書はユーザーの「まず設計の整理・確定、今回は実装には入らない」という指示を受けた実装者の採用判断である。ユーザー原文はTASK.mdへ別に保存する。前回レビューの提案をすべて追加機能として採用せず、現在の検索の意味と到達性を整える範囲に絞る。旧UI仕様は履歴として保持し、今回の対象については本書を後続実装の基準とする。

## 1. 目的と範囲

利用者が欲しいのは条件を操作することではなく、用途に合うカードと、そのカードが候補になる理由である。カードを知っている場合も、必要な効果しか分からない場合も、一つの検索で条件を重ねられる構成にする。

| 利用目的 | 自然な入口 | 結果で確認したいこと |
| --- | --- | --- |
| 特定の人物・カードを探す | カード検索、人物、P/S、シリーズ・入手 | 該当カードと基本情報 |
| 編成で必要な性能を探す | ライブ・思い出・パッシブ、欲しい効果、属性 | 一致したスキル・効果、条件、解放段階 |
| 育成用のSカードを探す | 育成サポート、体力・SP・レッスン等 | 何がどの場面で役立つか、所持ライブとの区別 |

採用範囲：項目の再配置・名称・条件表示、検索対象との整合、既存データによるパッシブ/上限の検索接続、PC/スマホの条件操作、旧URL互換、結果の一致理由。

今回の設計から外す追加機能：数値の以上/以下・範囲、発動条件の数値入力、所有カード管理、編成評価、別スキルをまたぐ条件群、効果の箇所を指定する新フィルター、Sアイデア/ひらめき/熟練度の新フィルター、期間プリセット、条件保存機能。これらは後続候補であり、この改修の完成条件にしない。

原本・取得・変換・配布のスキーマ変更、追加取得、新しい外部サービスや依存関係は必要としない。UI実装を変更した時点で初めてUI番号を更新する。本書作成だけでは更新しない。

## 3. 画面構成の確定

別々の検索モードや排他的なタブは作らない。人物から探し始めても性能条件を重ねられ、逆も可能にする。

| 表示順 | 見出し | 内容・初期状態 |
| --- | --- | --- |
| 1 | カード名・アイドル名など | 現行カード検索q。検索範囲はカード名/人物/ユニット/シリーズ等の基本情報 |
| 2 | P/S・レアリティ | 常時表示。複数選択、未選択は指定なし。UR/SSR/SR/R/Nを維持 |
| 3 | ユニット・アイドル | 上位の独立した一段の開閉。選択時は開く。開いた各ユニットの下では全アイドルを常時表示 |
| 4 | シリーズ・入手 | 指定8区分を常時表示。企画タグ・詳しい入手方法は同グループ内の補足欄 |
| 5 | スキル・性能から探す | 主な入口として見出しを常時表示。開くと探す情報→欲しい効果→属性→キーワードの順。性能条件があれば開く |
| 6 | 性能の詳しい条件 | ライブの種類、追加機能、パッシブ発動条件、効果の対象、継続。適用できる項目だけ提示 |

「スキル・性能から探す」を開く前に収録件数・技術説明の長文を読ませない。収録範囲はページの短い概要と補足へ整理し、選択した条件に関係する制限だけを近くで説明する。

PCの人物初期状態は閉、選択時開。スマホの条件パネルでも同じ。ユニット内のアイドルをさらに折りたたむ機能は作らない。公式の人物/ユニット順、コラボを独立した検索軸にしない方針を維持する。

## 4. 探す情報・項目名・入力の契約

「探す情報」は単一選択とし、指定なし/ライブスキル/パッシブスキル/育成サポートスキル/思い出アピール/ステータス上限UP/固有アビリティ/クイックスキルを表示する。「指定なし」はすべてを対象にする。

ライブはpanel_live/mb_live/generated_live/possessed_liveのOR集合。ライブを選んだ時に「ライブスキルの種類」でパネル/所持/MB/生成を複数選択できる。未選択は4種類すべて。パネルと所持は混ぜた名称にしない。MBはメモリーブーストの説明を添える。生成は生成元を結果に表示する。旧URLの複数skill_kindも内部ではORを維持する。

| 表示名 | 意味/入力 |
| --- | --- |
| カード名・アイドル名など | q。空白区切りはすべての語に一致。スキル本文まで横断しない |
| 探す情報 | skill_kindの既存値またはライブ4値の集合 |
| 欲しい効果 | effect_type。単一の末端条件を選択。分類見出しは選択値ではない |
| 効果の属性・能力 | effect_target。Vocal/Dance/Visualを先頭にし、残りは分野別の固定順 |
| スキル名・効果・条件のキーワード | skill_q。空白区切りはすべての語に一致。検索対象の部分範囲を短い補足で明示 |
| ライブスキルの追加機能 | mechanic。Link/Plus/Change/Grow・GrowUp/Refrain、複数はOR |
| 発動条件に含まれる要素 | skill_condition。パッシブ対象。メンタル/ターン/編成ポジション/参加アイドル/付与効果/履歴/所持キーワード/その他 |
| 効果の対象 | effect_recipient。自身/ライバル/全ユニット/全観客。明記されたもののみ |
| 効果の継続ターン | effect_turns。1/2/3/4/5/7/10ターン以上。下限が明記された効果のみ |
| 初回実装日 | from/to。年だけ・年月だけも可。空欄は指定なし、日付未確認は期間指定から除外 |
| 詳細収録済みのカードだけ | detail_status=available。収録状態であり、性能の有無ではない |

未選択を「全部チェック済み」と同じ表示にしない。P/Sは未選択なら両方、人物/区分/レアリティも未選択なら制限なし。並べ替えは絞り込み条件数に含めず、条件全解除でも現在の並べ替えを維持する。並べ替え自体の初期値は従来の初回実装日：新しい順。

### 4.1 効果の整理

54種類は調査台帳のproposed_effect_groupsへ重複なく割り当てた。見出しは「アピール・ライブの機能」「能力・ステータスの変化」「回復・ゲージ」「観客への効果」「育成サポート」「ランダム候補」。選択UIはグループ付きの単一selectを基本とし、新しい独自コンボボックスや分類タブは作らない。探す情報に合わせて関連する候補を提示する。

行動順は「指定あり/必ず最初/必ず最後」を同じ見出しへまとめる。超過回復、強化アピール、PERFECT変化、消去付き等は親効果の特徴として配置するが、内部の既存predicateを維持する。親と特徴を独立した二つのAND欄に増やさず、一つの末端選択値へ対応させる。複数の特徴の同時指定は今回追加しない。パッシブ/上限の読取接続で加える4値は「パッシブの効果」「ステータス上限」の見出しへ配置し、ライブの継続UPと混ぜない。

「アピール値UP」と「人物別アピール倍率UP」、「興味倍率」と「興味倍率の最小値」、体力とメンタル、パッシブのUPと継続UPは意味が異なるため統合しない。Refrainの機能タグは「その機能を持つライブ」、効果選択は「リフレイン効果そのもの」である。両方が同じ内容を制約する場合は選択中表示で関係を示すが、勝手にどちらかを削除しない。

Excellent/エクセレント等は、当面選択肢に意味の補足を付けて区別する。同義であると確認できない内部値を日本語表記だけで統合しない。表示順を原JSONの初出順に依存させない。

## 5. シリーズ・入手の確定仕様と旧URL

通常の上段はプレコレ/キャスコレ/パラコレ/トワコレ/マイコレ/期間限定/恒常/その他の順を維持。現在のmatchesBrowseの定義を変えない。「その他」は上記7区分以外であり、「シリーズ情報が不明」の意味にしない。複数区分はOR。

通常UIの補足欄「企画タグ」はbirthday/vote_selection/expansion/axe8等、8区分と重複しないseries_idsを表示。「詳しい入手方法」はcollection_gacha/event_reward/gacha_bonus/mission/campaign/exchange/other_bonus/initial/collaboration_gacha/other/unknown等、恒常/期間限定と重複しない値を表示する。実際に収録された値だけを辞書順で生成する。コレクションガシャは5区分をまたぐ入手方法なので残す。コラボガシャは入手方法の一値であり、コラボ作品を独立欄にしない。

上段の区分、企画タグ、詳しい入手方法は異なるグループとしてAND。企画タグ内・入手方法内はOR。「期間限定＋誕生日」はANDで自然に指定できる。誕生日を選んだだけで期間限定へ自動変更しない。

新しい通常操作では同じトワコレ/恒常/期間限定を二度選ぶ箇所を作らない。重複する現行の全系列一覧/全入手一覧は、次の互換条件がある場合だけ追加表示する。

| 入力URL | 表示/評価 |
| --- | --- |
| browseのみ | 通常の8区分として表示。ORを維持 |
| 非重複のseries_ids/acquisition_categoryのみ | 通常の企画/詳細入手欄へ表示 |
| 旧series_idsに5系列、旧acquisition_categoryに恒常/期間限定を含む | 「リンクの追加条件」欄を開き、元の軸とOR集合をそのまま表示 |
| browseと旧系列/入手条件が混在、または旧人物AND条件 | 元のグループ間AND/グループ内ORを維持。近道へ勝手に合流しない |

互換欄も個別解除・グループ解除・元の全選択肢の編集ができる。通常の区分との関係を「さらに絞り込む条件」と明示する。旧条件を残したまま新しい区分を選ぶ場合、両条件を表示する。「新しい方式への切替」を暗黙の上書き操作にしない。

理由：旧series_ids=(トワコレ または 誕生日)をbrowse=トワコレ AND 企画=誕生日へ変えると検索式が変わる。見た目の重複排除を理由に結果を変えてはならない。前回レビューの「近道と詳細を全面連動」は、この問題を避けるため通常UIの重複除去＋明示的互換欄へ修正した。

将来8区分の重複が生じても、優先順でどれかへ排他的に押し込めない。現在は8区分が重複なく1466件を覆うことと、将来も永久に排他的であることを混同しない。

## 6. 正確な一致判定

カード基本条件は現行search、詳細は同じdetail_idの中で評価する。画面と件数・URL・一致理由が同じ問い合わせ表現を使うことを必須にする。

論理契約：

1. 同じ多選択欄はOR。異なるグループはAND。テキストの空白区切りは全語AND。
2. 詳細の種類・機能・パッシブ発動条件・キーワードは同じ一つのスキル項目に一致する必要がある。
3. 効果/属性/対象/継続を指定した場合は、その同じスキル内の同じ一つの検索用効果へ一致させる。別効果の属性と期間をつぎはぎしない。
4. ランダム候補は明示選択した時だけ対象。属性・期間・キーワードは同じ候補に一致。候補の付与を保証しない。
5. 閾値や期間の不明は0/永続/隣の効果で補わない。期間範囲は最短、最大値しか分からない場合は継続以上条件から除外。
6. 機能タグはスキルの所持機能。Linkを選んでも「一致した効果がLink内で発生」を保証しない。結果に実際の通常/Link等の箇所を表示する。
7. 思い出Linkは現行のライブ機能タグの対象外。思い出のキーワード/効果検索で扱い、対応しないチェックを選べるようにしない。新しいscopeフィルターは今回追加しない。

これまでのskill_qは、効果欄未指定時には同じスキルの検索可能な情報全体に一致し、効果欄指定時には同じ効果と共通のスキル情報に限定する。この既存の範囲差を維持して短いヘルプで説明し、単に全文検索と呼ばない。初回改修でスキル全文・原Wiki本文へ勝手に拡張しない。

### 6.1 パッシブ・上限の接続

原本や公開JSONを書き換えず、検索時の読取専用アダプターで検索用の効果を作る。既存effect_details.effectsを持つ種類はそれを唯一の効果ソースとし、同じライブ効果をnumeric_factsから二重生成しない。

| 元情報 | 検索用の意味 | 制約 |
| --- | --- | --- |
| panel_passive.numeric_factsのmetric=rate、direction=UP/DOWN/CUT | passive_up/passive_down/passive_cut（パッシブのUP/DOWN/CUT効果） | target/明記targetsを保持。発動確率・発動上限回数は効果にしない |
| cap_increase.cap_targetsとcap_delta | cap_increase（ステータス上限UP） | 1ノードの対象/増分。カード全体の合計上限へ集計しない |

検索用効果には元のdetail_idと元フィールド/配列位置を保持し、検索と強調表示で同じ参照を使う。固定IDを振り直さず、この一時表現を原本へ逆流させない。パッシブに継続期間や対象=自身を推定して付けない。複合効果は原本が分離している事実単位のまま扱う。

パッシブ/上限の効果＋属性検索は今回必要な整合修正である。現在保存先の違いで検索できない値を接続するもので、新規取得や全数値検索への拡張ではない。値の以上/以下、発動確率の数値絞り込み、特訓段階の新フィルターは追加しない。SP/特訓/Lv/MB段階は一致理由に表示し、未解放でも自動的に使用可能と見なさない。

旧URLも基本のAND/ORは維持する。ただしパッシブ/上限＋属性で誤って0件となる現行の保存先由来の制限は、この整合修正によって結果が増えうる。これは仕様変更としてリリース時に明示する。歴史的な結果を厳密に再現するにはUI24と旧不変データの組を用いる。

### 6.2 適用可能性と0件

選択肢の表示可能性は探す情報/P/S/効果の意味と収録内容で判断する。現在の検索結果が0件だからという理由だけで選択肢を消したり、選択済み条件を無効化しない。ORを追加して件数を増やす操作を妨げない。選択肢ごとの動的件数は今回追加しない。

種類を変更して以前の条件が対象外になっても自動削除しない。対象外になった選択は選択中の条件と該当グループに残し、「S用の条件が残っています」「パッシブには継続ターンを指定できません」等の理由とその条件だけの解除を提示する。

対象外/入力不正は「条件を適用できません」という状態に分ける。PCでは結果欄をその案内に置き換え、前の結果を新条件の結果として残さない。スマホでは新条件の適用を止め、結果画面の適用済み条件は維持する。正しく評価できる条件で該当がない場合だけ0件と表示する。

0件時は選択中の条件、グループ解除、全解除を表示し、スキル未収録/効果検索の対応範囲も短く案内する。「ゲーム内に存在しない」とは断言しない。期間未記載10項目は指定スキップ済みとして扱い、再確認待ちへ戻さない。

## 7. 選択中の条件と一致理由

選択中表示は「カード」「シリーズ・入手」「スキル・性能」「詳しい条件」のまとまりで結果見出し付近に置く。スマホの条件パネルを閉じても選択数と解除導線を残す。ORは「SSR または UR」、異なるまとまりは「すべて満たす」と表示する。並べ替えは別表示。

例：カード［S］［SSR］ / スキル・性能［パッシブ］［UP効果］［Vocal］ / 発動条件に含む［メンタル］。

各チップの解除に加え、人物だけ/性能だけ等のグループ解除、全条件解除を設ける。全条件解除は絞り込みだけを解除して並べ替えを維持。既知の検索キーの未対応値は黙って捨てず、既存互換評価で扱えるものは表示し、評価できないものは対象外状態として解除可能にする。検索キーでないURL情報（utm等）は検索へ影響させず、条件数に含めない。

性能検索時の一覧には「一致：スキル名・効果の短い要約」を最大1件と「ほかN件」を表示する。通常のカード検索だけなら表示しない。一致効果が複数あることは保持し、詳細を開いたら一致項目を先頭へ、実際の効果/パッシブ数値/上限ノードを強調する。発動条件/特訓/Lv/効果の箇所は要約を確認する補足であり、候補カードが無条件でその効果を出せるという評価にしない。

現在の機能タグや発動条件だけでも一致スキルを示す。現在のapp.mjsは効果欄またはskill_qがある時だけ一致項目を先頭にするため、この表示判定も共通の一致結果へ揃える。

## 8. PCとスマホの状態遷移

状態を「適用済み条件」と「編集中の条件」に分ける。検索評価・URLの意味は端末で同じ。適用タイミングだけを変える。

### PC（900px以上）

左に条件、右に結果。主要条件・選択中条件・件数へすぐ到達できるようにする。条件列全体を長大な固定スクロール領域にしない。

チェック/選択は有効なら即時適用。文字入力はIME変換中の再検索を避け、変換確定後に短い待ちを置く。日付は有効な確定値だけを反映し、入力途中/不正な日付で意図せず期間を解除しない。開始＞終了はエラーとして修正を促す。適用状態が不正なら6.2の案内に分ける。

### スマホ・タブレット（900px未満）

カード検索とP/S・レアリティ、件数、選択中条件の要約を結果の上へ置き、「絞り込み（N）」で専用パネルを開く。人物/区分/性能/その他をその中で編集する。結果は現在の簡潔な縦一覧、タップで詳細を維持する。

| 操作 | 状態/URL/フォーカス |
| --- | --- |
| 絞り込みを開く | 適用済みから編集用のコピーを作り、パネルの見出しへフォーカス |
| 条件を編集 | 編集用だけ更新。URL/結果一覧は変更しない。パネル内の予定件数のみ同じ検索式で更新 |
| ○件を表示 | 妥当なら一括適用、URL履歴は1回更新、パネルを閉じ結果見出しへ。0件でも適用可能 |
| キャンセル/閉じる/Escape | 編集内容を破棄して元の起動ボタンへ。暗黙の適用にしない |
| ブラウザの戻るでパネルを閉じる | 編集を破棄する。パネル開閉用の一時履歴は条件適用履歴へ置換し、余分な戻る段数を残さない |
| 適用済みチップを解除 | 結果側で即時適用。パネルを開いている間は背景を操作不可にする |
| 日付方式を切替 | 同じ編集値を保持。カレンダー/年月日で別の条件を持たない |
| パネル編集中にPC幅へ変更 | 編集は自動適用せず取り消し、適用済み条件からPC表示へ戻す。取り消しを通知 |
| PCからスマホ幅へ変更 | 適用済み条件を維持。パネルは閉で表示 |

閉じるボタンにも「変更を破棄して閉じる」の補足を付け、適用ボタンと役割を分ける。固定フッターは「○件を表示」だけに絞り、キーボード/セーフエリアを避ける。0件を表示の時は「条件を減らすと見つかる可能性」を近くに提示する。

スマホ上部のカード検索/P/S・レアリティは即時反映。パネル内の同項目を編集する場合は編集中の値であり、背景の適用済み条件と混同させない。入力方法による即時/一括の違いを「このパネルではまとめて適用」と明記する。

タッチ領域は既存44px以上の方針を維持。ラベルと入力を関連付け、キーボード操作・見えるフォーカス・件数の控えめな読み上げ・パネル内フォーカスの管理・解除後のフォーカス先を実装条件に含める。全面的なWCAG適合を設計だけで宣言しない。
